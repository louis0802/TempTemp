# Design

Existing scripts/research/build-merchant-source-map.ts combines frozen corpus, corrected audit, explicit signal review, direct registry and social research. scripts/research/merchant-source-map/build.ts groups historical observations and derives multi-source progress through progress.ts. Social inventory separates exact account candidates from account-unresolved content; captured hashes and exact backlink verification protect ownership. Direct source adapters use bounded allowlisted transport and generic candidate/publication semantics.

Add an explicit reviewed canonical identity layer, without rewriting frozen records or changing normalization. Evidence claims reference hash-checked public captures and identity assertions; apply only reviewed same-merchant aliases to grouping and joins. Keep source-specific reviewed batch decisions separate from historical observations. Generator-backed reviewed web assessments supply missing researched tracks; runtime sources are registered only if an actual adapter is justified.

Capture each merchant independently into new immutable fixture directories with request/status/hash/bytes/purpose and bounded public-only transport. Inspect only explicit official roots, their bounded campaign/detail/location links and merchant-linked socials. Compose new social capture manifests with prior captures without modifying them. Derive exact content-account bindings from standard public metadata separately from official backlink ownership. Preserve unresolved content alongside independently verified profile candidates.

Implement useful web adapters only after deterministic structures are proven. Prefer existing source families and shared utilities, retain fail-closed limits, unknown continuation/classification/participation and generic publication gate. No DB migration, scheduler, or processor change is planned. Final reports and offline dry-run dispositions pin the Singapore observation date. Rollback consists of restoring this slice's files; no persistent production state changes.

## Evidence-based adapter choices

Four useful shadow adapters are justified: Bari Bari exact WordPress post cards/details; Captain Kim exact campaign sections on two official outlet pages and the standalone takeaway proposition; Sushiro explicitly linked WordPress campaign detail; McDonald’s two current public campaign pages isolated from its unresolved news load-more and wider homepage campaigns. Gelare’s gallery has opaque titles and image-only facts, so no placeholder adapter is planned. Kimpson’s closed catalogue, Singapore-unestablished More Yogurt global news, Shiok’s menu/news-only page, 4Fingers/Pizza Hut JS shells, Kei’s cached third-party Instagram widget and Coffee Bean’s commerce/social home do not establish complete autonomous promotion directories.

All four adapters remain disabled. Bari grid Ajax continuation, Captain image-to-text proposition equivalence and outside-index campaigns, Sushiro media/year/outlet scope, and McDonald’s directory completeness/multiple propositions/outlet authority are explicit blockers. No new publication processor semantics or DB work.

## Final implementation details

merchant-source-map/identity.ts checks explicit merchant_self_identification aliases against immutable capture hashes and distinct exact title/description assertions, rejecting similarity/operator-only inputs and cycles. Canonical identity is used in historical grouping and registry/audit/social joins, without changing normalizeIdentity or frozen inputs. All historical labels and post/offer identities survive.

merchant-source-map/assessments.ts validates source-decisions.json capture hashes and reviewed web assessments. A shadow claim requires a real matching disabled registry source; missing/unknown adapters fail the join. Generator precedence remains in progress.ts. Reviewed research tracks do not create runtime authority. Accountless content stays separate even where an owned profile is independently known and blocked.

Social resolution reads standard canonical/Open Graph/native identity and exact author links only; numeric Facebook native/account identity remains separate. Unsupportedbrowser is transport only. Additional capture manifests compose prior evidence without modifying it. Only accounts with actual probes receive acquisition assessments. The inventory and authority review explicitly record account outcomes. Exact public HTTP profile hyperlinks may be upgraded to HTTPS only while preserving platform/account; wrong ownership links fail. No permissive runtime social scope is added.

coverage-batch-2-definitions.ts appends four disabled definitions; adapters/coverage-batch-2.ts contains separate evidence-grounded parsers sharing only conservative textual candidate construction and exact-detail fetching. Bari facts come from own listing cards because its detail template shows related posts. Captain uses exact page/section native IDs and leaves participation unresolved. Sushiro isolates its linked card/detail and never infers a year. McDonald's meal documents never inherit embedded contest dates. Native/card/detail changes, unknown pagination, foreign URLs, limits and missing facts fail closed.

The generic gate produces 15 offline candidates: 1 explicitly expired Captain campaign excluded, 14 review and 0 ready. These are not persisted queues or production publications. No physical branch scope or coordinates are fabricated. All four source definitions remain disabled, and source-level limitations are evaluated in adapter output in addition to registry review metadata. The authoritative publication/persistence processor remains direct-source-v2.

The merged canonical row explicitly retains sorted historical signal URLs and offer IDs in canonical_identity_review, along with every alias/canonical/reason/capture hash. CSV headers include reviewed row-specific fields so this audit survives both JSON and CSV. Generated Markdown identifies the reviewed merge. Landlord observations remain evidence references, never merchant-owned web acquisition roots.
