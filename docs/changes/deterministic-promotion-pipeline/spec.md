# Specification
AC1: Resolve relative dates from Singapore post date, inclusive expiry, conservative year inference, weekday restrictions and separate redemption hours/last order. Unknown or contradictory dates cannot approve.
AC2: Separate numbered offers without transferring local terms. Clearly shared metadata may apply across offers; incompatible branch/product periods require a structured split blocker.
AC3: Distinguish all, excluded, selected, named, online and unclear scopes. Selected participation requires its own list; named participation never expands. Online ordering alone does not exclude physical redemption.
AC4: All-outlet approval requires authoritative complete enumeration, reconciled count when available, status filtering, explicit exclusion audit, and every eligible branch resolved. Places search never proves enumeration or participation.
AC5: Each outlet has distinct existence, participation and coordinate evidence and conservative precision; identity is stable only for the same physical branch.
AC6: Approve only verified current genuine offers passing schema/business validation with complete audit. Missing core facts/media, conflicts, failed dependencies and future offers remain unresolved. Expired, clearly non-promotional, online-only and duplicate offers are excluded.
AC7: Cache external resolutions with timestamps, URL and content hashes. Return/persist explanations; preserve candidate review API and existing publication reconciliation.
AC8: Tests cover supplied patterns and representative real inbox records, provider failures and publication safety; live credentials are not required for repeatable tests.

Assumptions: ambiguous extraction stays reviewable. Initial real merchant coverage is Genki Sushi, present in the inbox; unsupported chains remain unresolved until an authoritative adapter is installed. Media/link terms are not treated as verified merely because text parses.

## Google discovery follow-on
AC9: When a merchant has no directory adapter, search Google Places using merchant plus each explicitly participating branch. Accept only a unique Singapore operating result matching merchant, branch/address and stated unit. The source establishes participation; Google establishes existence and location. Ambiguity or missing identity facts remain unresolved.
AC10: All-outlet offers without adapters still search for merchant branches and retain useful location evidence. Search results remain explicitly non-authoritative and cannot alone complete a chain audit, even after consuming search pagination.
AC11: Selected outlets can use Google lookup only after the complete promotion-specific participation list is established. Do not turn merchant search results into a selected-outlet list.
AC12: Cache paginated search results, deduplicate by place ID, retain response evidence, bound requests, report missing credentials/failures clearly, and reuse returned coordinates without redundant geocoding. Existing review/publication APIs remain unchanged.
