# Specification

1. Read dated local Telegram raw evidence, deduplicate channel/message ID and select newest promotion signals by publication time. Retain non-offer posts inspected before the sample boundary. Signals are individual parsed offers; a roundup can yield several. Promotional intent qualifies for research sampling, not publication eligibility. Clearly editorial lists, launches and ordinary menu announcements without an offer are excluded from the promotion denominator.
2. Resolve only links extracted from selected promotion signals. Keep original representations, association, all redirect hops, failure reasons and HTTP status. Shared links resolve once per cache. A successful final URL with unknown topology differs from a failed redirect.
3. Observe merchant web, social, issuer/platform, app/deep link, publisher, aggregator, Telegram, hub, shortener and unknown topology separately from ownership. Known discovery surfaces stay intermediate even if reached successfully. Publisher records explicitly require deeper resolution; this version does not inspect article bodies.
4. Without a production registry match or explicit research ownership evidence, authority remains unknown for candidate destinations. A scoped research review can upgrade only matching merchant/host/account/path and retains its evidence note; it never changes production registry data.
5. Frozen and refreshed inputs are never merged. Explicit refresh uses a bounded one-off public preview collection; all records name their input mode. Offline runs use only supplied/local cache and inputs, never network. Inputs and sealed evidence remain unchanged.
6. Separate local output contains signals.json, resolved-links.json, audit.json, report.md and report.csv. Include all requested counts, unique/repeated domains, destination and adapter counts, and unweighted adapter-family concentration. Counts explicitly distinguish unique URLs, offers, posts and link records. Offer-origin metrics use offer-associated links only; neighboring source-post links are retained as separately counted context, never used to establish this offer's origin. No-link and non-offer records remain visible.
7. Same inputs, cache and review produce byte-stable semantic audit output. Runtime timestamps belong in provenance outside the semantic audit. Reports must disclose sample shortfalls, parser uncertainty, incomplete ownership, unknown enumerability and untested extraction feasibility.

Acceptance: focused tests cover merchant, publisher, hub/Telegram, social, scoped override, shared cache, loop/timeout/private DNS, editorial/no-link posts, stable rerun, input immutability and absence of production dependencies. Typecheck/lint/format/diff checks pass. After tests, run sample 50 from frozen inputs first; refresh explicitly if fewer than 30 promotion signals. Report actual counts and verified side-effect boundaries.

No consequential product decisions remain open. Candidate topology is a research observation and cannot certify source ownership or completeness.
