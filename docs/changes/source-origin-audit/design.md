# Design

An independent scripts/research/source-origin-audit.ts CLI calls a research-only module. Reuse createSignals and PostOfferParser, production source types, extractLinks via createSignals, classifySource, SourceLinkResolver and SourceRedirectCache unchanged. No ingestion runner, persistence, application routes or monitor lifecycle imports.

Input reads runs/*/telegram-raw.json in sorted snapshot order. Latest dated snapshot wins for duplicate post identity (edits stay attributed to that snapshot). Validate identities/timestamps/text, rebuild permalinks from channel/ID, and sort descending publication time with stable tie breaks. Retain source file provenance. Parse intent conservatively; editorial posts have a dedicated retained signal row. Stop at the requested parsed promotion count. Offer rows keep association to source-post-level links rather than asserting offer relevance.

Network allowlist is built exclusively from selected promotion outbound links. Sequential unique-link resolution uses the existing cache, DNS pinning and no-body resolver. A persistent research redirect cache allows offline deterministic replay. Failed or blocked hops remain intact. Explicit refresh uses collectPreview for both allowlisted channels over a bounded historical window; refreshed raw inputs are saved only in the new audit directory and replace frozen inputs for that run.

Research topology classifies each redirect hop and final HTTP destination. Unregistered ordinary web pages are provisional merchant_web_candidate, never ownership claims. Known publisher/social/platform/app/hub/shortener surfaces are distinguished first. Adapter family uses conservative host/path observations; enumerability and extraction feasibility remain unknown or not assessed because bodies are not read. Publisher final destinations append a deeper-resolution requirement rather than inventing a merchant hop.

Optional strict versioned research review schema uses exact normalized merchant/host and segment-bounded account/path scope. Shared social hosts require account/path. Conflicting matching entries fail closed. Only primary or strong_secondary explicit evidence can upgrade candidate authority. Known intermediate topology cannot become a direct source through an override. official_source_url is set only for verified candidate destinations.

Audit records are per signal/link, with a no-link placeholder. Summary counts mostly use distinct promotion signal IDs, link topology counts use offer-associated records, shortlink counts use unique original normalized URLs, and concentration counts distinct signal IDs within each family. Non-offers and neighboring source-post links are excluded from all promotion-origin counts. Context associations remain in audit records with a separate count. Domains also expose unique-original-URL counts to avoid mistaking repeated roundup associations for independent evidence. Google /url wrappers are intermediate hubs; the observed Happy Point app host is an app candidate. Semantic JSON has no generated timestamps; input provenance includes SHA-256 and mode, and resolution timestamps remain in resolved-links.json/cache.

Output paths are constrained to a separate research directory; realpath checks reject aliases/symlinks into frozen evidence or production data. No rollback/migration is needed: delete a generated run to discard it. Preserve historical source-substitution files untouched.
