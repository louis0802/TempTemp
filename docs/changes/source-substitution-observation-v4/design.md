# Design
Extend the existing file-only scripts/research/source-monitor service. Add separately hashed protocol-revision-4.json and source-registry-revision-4.json; loader accepts explicit historical revision, defaulting to 4. Existing active revision-3 runs continue with revision-3 semantics until close; new intervals use revision 4. No historical recalculation or data migration.

Telegram keeps raw acquisition outcomes, adds scheduled_slot and lateness_ms, and exposes derived slot outcomes. Revision-3 elapsed-gap coverage stays available. Revision 4 checks scheduled slots and successful completion within five minutes, with valid snapshot boundaries. Source polling uses durable per-pass directories under discovery/passes/<slot>/; the first pass captures all classes, later three-hour slots only fresh publishers. Missing earlier slots are recorded, never replayed as timely. Completed checkpoints survive restart. Daily merged result and acquisition freeze include all pass evidence; seals include the discovery tree. Prior daily results carry earliest candidate times and occurrences across disappearances.

Tracker composes existing interval/seal/evaluation readers, registry, snapshots and Telegram coverage. Runtime counters stay out of the stable design-flow document. Adapter capability metadata is derived from actual parser dispatch, with semantic extraction conservatively generic. Production-ready remains false. Match-based merchant coverage is reported separately from exact/probable offer coverage; no unreviewed fuzzy matching.

Rollout: code only, no service start/restart. An existing revision-3 process can finish its rehearsal with old code; revision-aware new worker may resume it without reclassifying it. Start before the next intended scoring day to establish baselines. Long acquisition, unsupported sources, public-preview limitations and sample insufficiency remain visible.

Shared read-only helpers in passes.ts provide current pass summaries and the next source schedule boundary to status/tracker. The tracker reuses verified sealed evaluations for cumulative metrics. It validates frozen reviewed match provenance independently of scoring eligibility, allowing descriptive rehearsal cases without promoting them into recall. Source limitations across all daily snapshots remain visible, even if a later capture improves.

The tracker reports all-protocol scored metrics for context and a separate revision-4 aggregate for the forward checkpoint. It uses the pinned interval revision, rather than an evaluation label, to select revision-4 days. Stage and next-gate progression use only that revision-4 aggregate.
