# Revision 6 runtime completeness repair — design

Add a typed snapshot classifier with explicit structural enumeration blockers and separate semantic/detail diagnostics. Never use broad snapshot status as an enumeration predicate. Revision-6 acquisition summarization reads scheduled passes/recovery artifacts directly; leave summarizeRev5Acquisition and evaluateRevision5 unchanged. Combine per-source failed windows with strict recovery coverage rather than hiding failed live snapshots when any cadence gap exists.

Harden recovery-checkpoint construction and read validation. New checkpoints carry explicit boundary/order proof; legacy terminal, nontruncated dated checkpoints may be accepted after structural validation. Reject legacy truncation/unproven boundaries without deleting files. Atomic writes retain the previous valid checkpoint on invalid proposals or older observations.

Pass validated durable traversal targets from the rev6 tiered service into runDiscovery. Reuse recovery_traversal for live proof; preserve legacy capture behavior outside rev6. Record bootstrap ordering/boundary diagnostics for rev6, and retain actual terminal-page state independently of successfully finished incremental pagination. Existing exact overlap and deterministic extra-page checks remain strict. Extend rev6 recovery triggering to structural acquisition failures as well as missed slots; rev5 triggering remains unchanged.

Tracker reads classifier and checkpoint validation diagnostics, exposing dimensions and precise core blocker reasons. Freeze new diagnostic fields with rev6 acquisition data. No evaluator formula or manual-review contract changes are required. `analysis.ts` excludes September 30 rev6 evaluations from service cumulative/tracker analysis only, leaving legacy revisions and retained evaluator outputs intact. This is an operational implementation-transition exclusion, not a new protocol reason or a rewrite of interval evidence.

Shared checkpoint persistence/read paths reject unsafe mutable runtime proof for all revisions; historical acquisition summarizers and evaluators remain unchanged. Legacy ConfirmGood category-scope warnings do not invalidate its dated archive checkpoint boundary, while rev6 enumeration still blocks actual required untraversed categories. New checkpoint proposals are schema/boundary-validated before atomic writes and cannot regress the observation timestamp. Only expired structural windows of complete-capable core sources add rev6 recovery triggers; supplemental limitations cannot create repeated redundant recoveries. Cadence calculations are unchanged.

Each rev6 failed/missed window ends at its registered cadence deadline (bounded by the requested observation cutoff). A strict morning recovery can cover that window while later successful live observations cover the rest of the day. Requiring the same proof to extend through an unrelated future day-end would reject valid interval coverage and is retained only in the unchanged rev5 summarizer. URL/hash, ordering, pagination, cap and reason checks remain strict; an unresolved pagination control on the deterministic overlap page prevents rev6 recovery completeness.

Before any activation preserve .local evidence. Controlled tests use temporary roots and fixture HTTP only. Protected-file hash comparison distinguishes ongoing worker writes from this task's writes; sealed files and frozen assets must remain byte-identical. Do not restart/start a worker during this implementation unless operational inspection establishes a necessary authorized restart with the same data directory.
