# Design

Keep the unchanged SourceLinkResolver and its cache as transport evidence. Add a pure helper in the source-origin research classification module that accepts a resolved final URL and chain. Preserve resolved_url as the legacy transport field; add transport_final_url/domain, canonical_candidate_url, candidate_domain and canonicalization_basis. Candidate classification, authority lookup and domain/family metrics use the candidate. Exact unsupportedbrowser with an immediately preceding recognized Instagram content URL (or recognized Facebook content URL) is the only recovery rule. No search through arbitrary older hops. Failed resolutions never gain a canonical URL.

Use existing auditSignals for same-mode captured offline replay, retaining original signal/cache provenance. New direct-source CLI has only local file/node and research schema dependencies; it consumes corrected audit records rather than resolving URLs again. Selection includes offer-associated resolved promotion records only and retains original record indexes/full records.

Direct-source evidence is a separately captured research JSON bundle with public page URL, transport/access observations, text/HTML fingerprints and categorical reviewer findings. No automatic domain ownership inference or production parser. Validate findings with Zod: explicit evidence references for verified ownership, listing observations for enumeration, independent field/access categories, app/web surface distinctions. A missing finding yields an unverified/inaccessible-or-unassessed record, never omission. Capture only candidate bodies and relevant observed same-source surfaces; external official corporate ownership references are narrowly scoped when necessary.

Artifacts include immutable input/evidence hashes, complete linkage, categorical counts, unique domain-pattern concentration, sections and per-record evidence. Output path restricts writes to new `.local/direct-source-audit` children, rejects aliases/overwrite. Offline output has no wall-clock-dependent semantic fields. Tests use small captured fixtures and temporary roots. No Next.js UI/routes are changed; repository-local Next guides are inspected for project compatibility, but this slice is Node research tooling.

## Implemented evidence and category boundaries

The new layer is intentionally offline: public capture/inspection and categorical researcher review precede CLI replay. Each supplied capture artifact is hashed and checked inside the evidence directory before output creation. Referenced inaccessible captures cannot establish verified ownership. There is no production parser or network transport in the direct-source CLI.

`enumerable` describes the observed source within its explicit boundary, independently from whether the sampled historical offer appears in the current listing. Happy Point and the sampled Kris+ Branch alias are non-enumerable app gateways; Kris+'s separate public web directory is recorded in app findings and recommendations, outside candidate enumeration counts. Paradise has a partially enumerable current corporate/brand surface, while its sampled old PDF is evidence-only and absent from the current menu link. A blocked product body can coexist with a partially enumerable sale catalogue on the same domain.

`domain_pattern_counts` counts all distinct domain/pattern observations; `reusable_domain_pattern_counts` filters to affirmative reusable observations. Repeated CS Foods offers contribute seven candidate observations but one WooCommerce domain pattern. No numerical ranking is introduced.

The actual native PDF inspection found a multi-column tiered price table; layout associations are a constraint, not a generated promotion parser. The FairPrice JSON-LD has a trailing brace and a rolling price-validity horizon that differs from visible campaign expiry; source evidence is preserved and this remains semi-structured, not blindly trusted structured campaign data.
